# 002 · 手机端：为什么看不到，以及怎么装上去

- **状态**：待用户选择安装路径
- **背景**：v11 做了手机端工具卡（`lifegame_today` / `lifegame_update`），桌面端正常，手机端什么都看不到。

---

## 1. 根本原因（已核实）

**手机跑的是它自己的本机引擎，而那套引擎的 profile 里没有这个插件。**

证据：

```
~/.dsh/ds-harness-remote/servers/<id>/host/trusted-peers.json
→ 3 个 peer，全部 platform: "web"，name: "当前浏览器"
→ 没有任何 android / mobile 设备
```

即：**这台 Mac 从来没有被手机配对过**。所以手机上的 DSH 是手机内置的那套，插件装在这台 Mac 的 `desktop` profile 里，两边互不相干。

这也解释了为什么：
- 手机看不到侧栏面板（客户端插件在手机引擎里不存在）
- 手机看不到工具卡（工具在手机引擎里不存在）

而 DSH Go 原生界面**不执行插件代码**、只渲染 `dsh-go/view` 的 JSON——所以「手机上装 Web 插件」本来也走不通，只能装到**手机正在跑的那套引擎**上。

---

## 2. 三条路

| 路 | 做法 | 工具卡能不能看到 | 适合 |
|----|------|------------------|------|
| **A. 手机 Remote 连这台 Mac** | 手机 App 里连本机主机（走 DSH Harness Remote，配对这台 Mac） | ✅ 能——工具卡「任何主机都能显示」 | 想用常开 Mac 当大脑，数据只存一处 |
| **B. 把插件装到手机本机引擎** | 手机 App 的「终端」里执行安装命令 | ✅ 能——工具在手机引擎里 | 想脱离电脑也能用，但数据在手机上，与 Mac 不同步 |
| **C. 手机连另一台常开 Mac** | 在那台 Mac 装插件并配对 | ✅ 能 | 你原本设想的部署形态 |

**推荐 A**：实施最快（不用装插件），且符合「常开 Mac 当大脑、数据只有一份」的原始设想。

---

## 3. 安装产物（B / C 用）

已打包：`plugin/local-lifegame-0.1.0.tgz`（14 KB，7 个文件）

在**目标机器**（手机本机引擎的 App 终端，或另一台 Mac 的终端）执行：

```sh
dsh plugin --profile web add /绝对路径/local-lifegame-0.1.0.tgz
```

装完重启那个引擎，然后在对话里说「**今天做什么**」，应调 `lifegame_today` 出卡。

> 注意：`--profile web` 是官方文档示例里的 profile 名；实际用目标机器上的 profile 名（`echo $DSH_PROFILE`）。
> 手机本机引擎的终端在 DSH Go 里可以直接用；把 tgz 传进手机可用文件分享或局域网下载。

---

## 4. 已验证：工具在这台 Mac 上注册成功

用一个新启动的子代理查它自己的工具表，返回：

```json
{"lifegame_tools": ["lifegame_today", "lifegame_update"], "has_notes_create": true}
```

结论：**注册没问题**。本会话看不到它们，只是因为本会话的工具表是重启前生成的（会话跨重启延续，工具目录不刷新）。**新建的会话里这两个工具都在。**

所以手机端看不到，唯一原因就是第 1 节那条：**插件不在手机正在跑的那套引擎里**。

## 6. 手机已连 Mac，但「没地方打开」——机制澄清（2026-11-25 晚）

用户反馈：**手机已经连上这台电脑了，但「人生游戏」没地方打开。**

### 6.1 连上 ≠ 有入口

手机连 Remote 后，**会话跑在这台 Mac 的引擎里**（所以工具可用），但**界面仍然是 DSH Go 的原生 Flutter 界面**。原生界面不执行 `client.js`，只渲染 JSON 视图。

所以：

| 入口 | 桌面 Web | 手机 Remote 连 Mac | 手机本机引擎 |
|------|----------|--------------------|--------------|
| 侧栏面板（`main` + `sidebar.panellist`） | ✅ | ❌ 原生 UI 不执行 | ❌ 同左 |
| **工具卡**（`presentationMeta`） | ✅ 通用卡 | ✅ **唯一可用入口** | ✅ |
| 胶囊 / 状态条 / 原生面板（`dshGo` 插槽） | ❌ | ❌ **桥接只在本机引擎** | ✅ |

官方图里那一行是关键：`package.json "dshGo" + ctx.dshGo → dsh-go 桥接 → App：原生插槽（**本机引擎**）`。

**结论：Remote 模式下手机上是没有"应用入口"的，只有对话。** 这不是漏做，是平台分工。

### 6.2 已补上的部分（为「本机引擎」准备）

`package.json` 增加 `dshGo` 清单：

- `panels`：`today` 面板，挂 `chat.panel` + `session.tab`
- `composer.strip`：输入框上方状态条，显示「今天 1/3」，点开进面板
- 面板视图带 `actions` 按钮：**做了 / 换一个**（工具卡里不显示，面板里显示）

`index.js` 用 `ctx.inject(["dshGo"], …)` 注册 `panel` 与 `strip`，点按返回白名单效果（`{ toast, refresh }`）。
**没有把 `dshGo` 写进顶层 `inject`**——官方要求如此，否则在没有桥接的主机上整个插件起不来。

验证：模拟 ctx 跑通，注册顺序为 route → tool → panel → strip；工具卡视图 671 B（上限 8 KiB），无 `undefined`。

### 6.3 所以「有地方打开」只有一条路

要手机上有入口（胶囊"今天"、状态条、带按钮的面板），**插件必须跑在手机本机引擎上**：

```sh
# 手机 App 的终端里
dsh plugin --profile web add /路径/local-lifegame-0.1.0.tgz
```

代价是数据落在手机上，与 Mac 不同步（除非后续做同步）。

如果继续用 Remote 连 Mac，入口就是**对话**：说「今天做什么」。
